# GateMatrix - VPNGate 多出口落地代理矩阵开发设计规范 (V2.0 终极架构版)

## 1. 架构演进与核心决策背景

### 1.1 为什么放弃“公网裸开 5000 端口”？
1. **云防火墙配额限制**：主流机房（AWS/阿里云/甲骨文云）安全组通常限制 50~100 条规则，无法开放 5000 独立端口；
2. **扫描器攻击风险**：公网连续暴露 5000 端口会被 Shodan/Censys 频繁扫描爆破，导致宿主机句柄和带宽耗尽；
3. **客户端加载卡顿**：Clash/v2rayN 导入 5000 行重复节点会导致客户端严重卡死。

### 1.2 最终采纳的现代化架构：单端口多用户 + SOCKS5 解耦转接
* **外部入站**：采用 **VLESS-Reality（高位 TCP 8443，微软+苹果双伪装）** 与 **Hysteria 2（UDP 443 极速抗丢包）** 双栈；
* **内部转接**：采用 **本地回环（`127.0.0.1:55001 ~ 55000+N`）SOCKS5 代理** 作为 sing-box 与底层各个拨号网卡之间的解耦接力棒；
* **落地出站**：每个用户（UUID/Password）对应一个本地 SOCKS5 端口，严格匹配一个远端 VPNGate 志愿者家庭宽带隧道。

## 3. 防卡死与系统级调优规范

1. **宿主机网络安全隔离 (`route-nopull` & `route-noexec`)**：
   * 严禁底层 VPN 拨号修改 VPS 操作系统的全局默认路由（Default Gateway）。
   * 所有拨号流量仅在 `tun100+` 网卡和 `55001+` 端口之间定向流通，宿主机的 SSH、已有 Docker 网站完全不受影响。
2. **连接超时与僵尸进程自愈 (`ping-restart 30`)**：
   * 远端志愿者的家庭网络断网时，进程在 30 秒内超时自杀并释放内存；
   * Rust 探活引擎每 15 分钟淘汰死节点，平滑替补新挖出的优质节点。
3. **CPU 错峰防尖刺调度**：
   * 启动隧道时每隔 80ms 唤醒一个进程，彻底平抑 CPU 启动尖刺。
4. **宿主机内核优化 (`/etc/sysctl.conf`)**：
   ```ini
   fs.file-max = 2097152
   net.ipv4.ip_local_port_range = 10000 65535
   net.core.somaxconn = 65535
   net.ipv4.tcp_max_syn_backlog = 16384
   ```

## 4. 交付文件与模块职责清单

* `deploy.sh`：交互式一键部署脚本，引导输入两个子域名并全自动拉起服务；
* `src/main.rs`：主程序入口，管理定时探活、规则渲染与隧道生命周期；
* `src/crawler.rs`：VPNGate CSV/API 高速异步解析器；
* `src/prober.rs`：Tokio 并发探活引擎（结合 RTT 延迟、上行带宽与在线时长加权打分）；
* `src/tunnel.rs`：底层隧道挂载器，完成 SOCKS5 桥接、注入防卡死策略并错峰拉起；
* `src/singbox.rs`：生成 Reality (双伪装) + Hysteria 2 双栈配置文件；
* `src/web.rs`：轻量 Web 看板与 Clash 一键订阅导出接口；
* `Dockerfile` & `docker-compose.yml`：基于 Alpine 构建的多阶段轻量运行镜像。
